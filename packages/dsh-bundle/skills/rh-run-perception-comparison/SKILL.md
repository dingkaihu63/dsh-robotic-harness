# 感知路线对比

固定检查顺序，同一输入、双路线、逐项对比。

1. **准备输入。** 确认输入图像/场景与运行参数（时间戳、来源）。两条路线必须使用**同一输入**，否则对比无效。
2. **执行双路线。** `rh_perception_run` 分别以 color 与 saliency 路线运行同一输入。记录每条路线的输出、耗时与原始输出路径。
3. **对比结果。** `rh_perception_compare` 对比两类结果：目标检出差异、位置/置信度差异、失败模式差异。
4. **分析路由选择。** 基于对比结果分析路由策略：什么条件下哪条路线更可靠（如低纹理场景 saliency 更稳、颜色干扰场景 color 更稳）。路由判断标注为推测。
5. **记录置信度。** 输出结果必须带 来源（图像/相机/路径）、时间戳、模型/算法版本。置信度仅作为证据之一，不单独作为结论依据。

## 成功判据

- 双路线在同一输入上完成，对比报告覆盖检出与置信度差异；所有结果带来源、时间戳与版本信息。

## 停止条件

- 输入不可用或两条路线输入不一致：停止，不允许用不同输入对比；某条路线后端不可用（`backend: "unavailable"`）时如实报告，不得用另一路线结果冒充。

## 常见误判

- 一次对比的成功率差异 ≠ 路线优劣结论——需要多样本与统计。
- 高置信度 ≠ 正确检出：感知输出永远需要交叉验证或人工确认。
