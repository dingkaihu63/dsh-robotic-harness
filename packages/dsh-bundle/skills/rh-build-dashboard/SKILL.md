# 生成工作台面板

固定检查顺序，先生成总览，再按需深化。

1. **生成面板。** `rh_dashboard_generate` 生成单文件仪表盘，汇总 `.rh` 目录下的运行与案例：状态、指标摘要、产物链接。记录生成路径。
2. **浏览内容。** 遍历面板中的运行/案例条目，确认覆盖范围（哪些 run 被纳入、哪些被排除）与排序/筛选依据。
3. **深化单个 run。** 对用户关注的单个 run：`rh_report_generate` 生成 Markdown 报告（含时间线），或用 `rh_timeline_export` 导出时间线视图。报告与面板互补，不是替代。
4. **解释面板。** 向用户说明面板内容与**限制**：面板是静态文件，非实时——数据只反映生成时刻，新 run 不会自动出现；重跑生成命令才会更新。

## 成功判据

- 面板已生成且可打开（单文件，无需服务器）；覆盖范围与筛选依据已说明，单个 run 的深化产物（如需）已生成。

## 停止条件

- `.rh` 目录不存在或无可用数据：停止并说明，不生成空面板充数。
- 面板生成失败（如产物缺失）：报告错误，不手动拼凑 HTML 冒充面板。

## 常见误判

- 面板看似"最新" ≠ 实时：必须提示这是静态快照，避免用户误读为新数据。
- 面板汇总 ≠ 诊断结论：具体 run 的问题要用 `rh_diagnose_run`/`rh_report_generate` 深化，面板只做入口。
